# LP 設計・実装ガイド

> プロジェクト設定・技術スタック・制約は [CLAUDE.md](/Users/uchan/d3m_condo_bylaws_pj/CLAUDE.md) を参照。

## 基本原則

- **モバイルファースト**: 全セクションをモバイルから設計し、デスクトップに拡張
- **ファーストビュー3秒ルール**: ヘッドラインで「誰のための」「何ができる」を即座に伝える
- **1ページ1ゴール**: 主CTAは1種類に絞り、ページ全体で3〜5回繰り返す
- **ベネフィット > 機能**: 機能説明ではなく、ユーザーが得る価値で語る
- **社会的証明**: 導入実績・権威性・お客様の声で信頼を構築

## セクション構成（推奨順序）

| 順番 | セクション | 目的 | 重要度 |
|------|-----------|------|--------|
| 1 | ヒーロー（ファーストビュー） | 価値提案を3秒以内に伝える | P0 |
| 2 | 課題提起（Pain Points） | ユーザーの痛みに共感 | P1 |
| 3 | 解決策（Solution） | サービスが課題をどう解決するか | P1 |
| 4 | 機能紹介（Features） | 主要機能を3〜5個、ベネフィット形式で | P1 |
| 5 | 使い方（How It Works） | 3ステップで導入の簡単さを訴求 | P1 |
| 6 | 社会的証明（Social Proof） | 導入事例・お客様の声・権威性 | P1 |
| 7 | 料金プラン（Pricing） | 明確で比較しやすい料金表 | P2 |
| 8 | FAQ | 購入障壁を取り除く | P2 |
| 9 | 最終CTA | 行動を促す最後の一押し | P0 |

## コピーライティング規則

### ヘッドライン
- **25〜40文字**（日本語）が最適長
- 主語は「あなた/ユーザー」にする（サービス主語ではなくユーザー主語）
- 「革新的」「画期的」「最先端」等の空虚な形容詞は禁止
- 具体的な数値・ベネフィットを含める

### パターン
1. **ベネフィット直球型**: 「〇〇を、△△だけで完結できる時代へ」
2. **課題→解決型**: 「〇〇に100万円？AIで□□を、あなたの手で」
3. **数値訴求型**: 「作業時間を1/10に。AIが△△から□□まで」

### マイクロコピー
- CTAボタン下: 「クレジットカード不要・1分で登録完了」
- フォーム横: 「メールアドレスは通知にのみ使用します」
- ボタンテキスト: 動詞 + ベネフィット形式（「無料で始める」「今すぐ試す」）

## 絶対守るべき技術制約

1. **フォントサイズ**: 本文18px以上、ボタン16px以上、注釈14px以上（高齢者対応）
2. **行間**: 日本語は 1.8〜2.0、段落間は行間の1.5倍以上
3. **コントラスト比**: 通常テキスト 4.5:1以上、大テキスト 3:1以上
4. **タッチターゲット**: ボタン・リンクは最小 48x48px、間隔 8px以上
5. **Core Web Vitals**: LCP < 2.5s、INP < 200ms、CLS < 0.1
6. **画像**: `next/image` 必須、ヒーロー画像は `priority` 付与
7. **フォント**: `next/font` でセルフホスティング、`display: swap`
8. **セマンティックHTML**: `<header>`, `<main>`, `<section>`, `<footer>` を適切に使用
9. **見出し階層**: `h1` は1ページ1つ、`h2` → `h3` の順序厳守
10. **スキップリンク**: ページ先頭に「本文へスキップ」リンクを配置

## 避けるべきこと

- スライダー/カルーセル（1枚目以降のCTR 1%未満）
- 抽象的なストックフォト
- 自動再生の動画
- 薄いグレーテキスト（#999 等のコントラスト不足）
- ホバーでのみ表示される情報
- `prefers-reduced-motion` を無視したアニメーション
- 料金を隠す（「お問い合わせください」はBtoC SaaSで離脱要因）
- 匿名のお客様の声

## エスカレーションプロトコル

以下の条件で作業を停止し、ユーザーに報告する:

- **3回の試行失敗**: 同じアプローチを3回試して解決しない場合
- **セキュリティの不確実性**: 認証、データ漏洩、非弁リスクに関する判断に迷う場合
- **ドメイン境界の逸脱**: 修正が複数ドメインにまたがり、影響範囲が不明確な場合

報告フォーマット:
- **REASON**: なぜ停止したか
- **ATTEMPTED**: 試行した内容（最大3つ）
- **RECOMMENDATION**: 推奨する次のステップ
