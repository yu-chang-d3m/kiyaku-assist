# コードレビュースキル

## Preamble（実行前チェック）

1. CLAUDE.md を読み、アーキテクチャ制約・技術制約を確認する
2. レビュー対象（PR URL、ブランチ名、または staged 変更）を特定する
3. `kiyaku-assist-v2/` 内の変更ファイルを確認する

## レビューの実行方法

### PR URL が指定された場合
```bash
gh pr diff {PR番号}
```
で差分を取得してレビュー。

### ブランチ名が指定された場合
```bash
git diff main...{ブランチ名}
```
で差分を取得してレビュー。

### 'staged' が指定された場合
```bash
git diff --cached
```
でステージング中の変更をレビュー。

### 引数なしの場合
```bash
git diff HEAD
```
で未コミットの全変更をレビュー。

## レビュー観点（6軸）

### 1. アーキテクチャ整合性
- **ドメイン境界違反**: `domains/` 間の直接依存がないか
- **依存方向**: `app/` → `domains/` → `shared/` の方向が守られているか
- **型の配置**: 型定義は `domains/{domain}/types.ts` にあるか、Zod スキーマは `shared/db/schemas.ts` にあるか
- **"use server" 制約**: `"use server"` ファイルから Zod スキーマを export していないか

### 2. Firebase / インフラ
- **SDK 使い分け**: サーバー側で Client SDK を使っていないか（Admin SDK が正解）
- **遅延初期化**: Firebase の初期化がモジュールレベルで行われていないか
- **セキュリティルール**: 新しいコレクションやフィールドへのアクセスルールは定義されているか
- **環境変数**: 新しい外部サービスの接続情報は `apphosting.yaml` に追加されているか
- **serverExternalPackages**: 新しいサーバー専用パッケージは `next.config.ts` に追加されているか

### 3. セキュリティ
- **認証バイパス**: API Route で認証チェックが漏れていないか
- **入力検証**: ユーザー入力に Zod バリデーションが適用されているか
- **非弁ガードレール**: チャット機能の変更で guardrails.ts のパターンが適切か
- **機密情報**: API キー、認証情報がハードコードされていないか
- **XSS / インジェクション**: ユーザー入力がそのまま HTML に埋め込まれていないか

### 4. アクセシビリティ
- **フォントサイズ**: 16px（`text-base`）未満のテキストがないか
- **タッチターゲット**: インタラクティブ要素が 44×44px 以上か
- **コントラスト比**: テキストと背景のコントラスト比が 4.5:1 以上か
- **色だけに頼らない**: 色情報にテキストや記号が併用されているか
- **印刷対応**: 新しい画面に `@media print` スタイルがあるか

### 5. コード品質
- **ハードコード値**: 環境変数や設定に切り出すべき値がハードコードされていないか
- **既存パターンとの一貫性**: UI パターン、命名規約、エラーハンドリングが既存コードと一致しているか
- **重複コード**: 既存のユーティリティや共有コンポーネントで代替できないか
- **エラーハンドリング**: try-catch が適切に使われているか、エラーレスポンス形式は統一されているか

### 6. テスト
- **ドメインロジック**: 新しいドメインロジックにユニットテストが追加されているか
- **API Route**: 新しいエンドポイントに API テストが追加されているか
- **E2E**: ユーザー向け機能に E2E テストシナリオが追加されているか
- **data-test 属性**: 新しいインタラクティブ要素に `data-test` 属性が付与されているか

## Codex 実装レビュー（特別チェック）

外部ツール（Codex等）で生成されたコードの追加チェック:
- **ハードコード値**: テスト用の値がそのまま残っていないか
- **環境差**: ローカル専用の設定が含まれていないか（`localhost`、`127.0.0.1`等）
- **UI重複**: 既存コンポーネントと重複する新しいコンポーネントが作られていないか
- **既存実装との一貫性**: インポートパス、命名規約、ファイル配置が既存に合っているか

詳細は [references/codex-review-checklist.md](references/codex-review-checklist.md) を参照。

## レビュー結果のフォーマット

```markdown
## レビュー結果

### 🔴 必須修正（ブロッカー）
- [項目]: 説明

### 🟡 推奨修正
- [項目]: 説明

### 🟢 良い点
- [項目]: 説明

### 💡 提案（任意）
- [項目]: 説明
```

## エスカレーションプロトコル

以下の条件で作業を停止し、ユーザーに報告する:

- **3回の試行失敗**: 同じアプローチを3回試して解決しない場合
- **セキュリティの不確実性**: 認証、データ漏洩、非弁リスクに関する判断に迷う場合
- **ドメイン境界の逸脱**: 修正が複数ドメインにまたがり、影響範囲が不明確な場合

報告フォーマット:
- **REASON**: なぜ停止したか
- **ATTEMPTED**: 試行した内容（最大3つ）
- **RECOMMENDATION**: 推奨する次のステップ

## 完了報告

実行結果を以下のいずれかで報告する:
- **DONE**: 6軸レビュー完了、指摘事項なし（または修正済み）
- **DONE_WITH_CONCERNS**: レビュー完了、未解決の指摘事項あり（リスト提示）
- **BLOCKED**: レビュー対象の取得に失敗（PR URL 無効等）
- **NEEDS_CONTEXT**: レビュー範囲や重点観点の指定が必要
